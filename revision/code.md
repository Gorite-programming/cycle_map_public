### アプリの構成と状態管理: C

- 文書では「MVI/UDF」となっているが、実際には一部だけ。
  - 画面の状態の多くは `MapScreenStateFactory.kt` の中の `mutableStateOf` (96 個) で持っている。
    状態の変化を表す型 (`MapUiIntent`) を使っている箇所は 20 ほど。
  - そのため、どこで状態が変わるかを追いにくい。
- `MapViewModel` を `remember { MapViewModel() }` で作っている (`MapScreenStateFactory.kt:367`)。
  - Android の仕組み (`viewModel()`) を通していないので、`onCleared` が呼ばれず、ViewModel にする意味が薄い。
  - `rememberSaveable` は 0 か所。メモリ不足などでアプリが裏で終了させられると、表示中のルートや入力中の内容が消える。
  - 画面の回転は、マニフェストの `configChanges` でアクティビティを作り直さないようにしているので問題ない。
- 今後の方向:
  - 状態を `MapViewModel` に集め、`viewModel()` で作る。
  - ナビ中のルートなど、消えると困るものは保存できる形にする。
  - 一度にすべて直すのではなく、検索・ルート・ナビのように画面の単位で少しずつ移すのが安全。
