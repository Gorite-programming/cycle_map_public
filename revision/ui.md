- 確認した画面: ホーム, ドロワー, オフラインデータ, 設定, 検索, POI 詳細, ルートプレビュー, ナビ (開始・終了確認), 保存済み, 記録, レイヤー選択, 3D 表示

## 総評

機能はそろっていて、見た目もまとまっている。
検索とナビの案内文に、使う人が迷う所が残っている。

## 直したほうがよい点 (優先度順)

### 1. 「コンビニ」と打っても 0 件になる

- 自由入力で「こんびに」「コンビニ」と検索すると「該当する目的地がありません」と出る。
  コンビニのタブを選んで同じ語を入れても 0 件。
- 一方、店名で「せぶん」と探すと 48 件出る。
  検索語を空にしてコンビニのタブを選べば、近い順に 50 件出る。
- 種類を表す言葉 (コンビニ、トイレ、駅など) が検索語として扱われていない。
  表示用の対応表 (`search/SearchHelper.kt` の `formatCategoryLabel`) はあるので、入力した語を種類の絞り込みに変える処理を足せば直せそう。
- 利用者が最初に打つ語なので、影響が一番大きい。

### 2. ナビの案内文に方向がない

- 画面上部の案内が「60m まもなく続けて分岐です」で、矢印は右折なのに文に「右」がない。
- `routing/IconResolver.kt:200` の `CONSECUTIVE_FORK` が、方向なしの固定の文 `"続けて分岐"` になっている。
- 音声だけで聞いた場合、どちらに曲がればよいかわからない。
  「右折、すぐ先を左」のような言い方が適切。

### 3. ナビ中の地図が狭い

- 下のパネル (速度・残り距離・勾配・標高グラフ) が画面の約 45% を占める。
- 停止中に速度 0 を大きく出すより、地図を広くしたほうが走行中は見やすい。
  パネルを畳める形がよい。

### 4. シートを広げると右側のボタンが隠れる

- ルートプレビューを広げたときと、記録のシートを開いたときに、＋/− ボタンがシートの下に半分隠れる。
- ルートプレビューを広げた状態では、目的地のピンがシートの縁に重なる。
  シートの高さに合わせて地図の表示範囲を合わせ直していないため。

## 小さめの改善点

- **ルートプレビュー**: どこからどこへのルートかが書かれていない (「現在地 → セブンイレブン…」のような表示がない)。
  平均速度の 15.0km/h は毎回同じ値なので、表示する意味が薄い。
- **天気**: 19 時でも太陽のアイコンが出る。説明文は「晴れ 夜遅く くもり」だった。
- **文言のずれ**: 保存済みタブの説明は「★アイコンから登録」だが、POI 詳細のボタンは「保存」と書かれている。
- **地図とステータスバーの重なり**: 地図の地名が上端のステータスバーに重なって読みにくい (3D では特に目立つ)。
  現在地の青い点に町名の文字が重なっている箇所もある。
- **POI 詳細**: シートを最大まで広げると、下半分が空白になる。
  情報が少ない店では、広げる高さを抑えたほうがよい。
- **オフラインデータ画面**: 「ルート探索用のデータ (5 県すべてそろっている)」と「地図タイルの保存 (地理院/OSM)」が並んでいて、通常表示しているベクター地図との関係がわかりにくい。
- **ドロワー**: 「目的地検索」は検索バーと、「3D地形ビュー」は 3D ボタンと同じ機能で、重複している。
- **データの分類**: 検索結果で「ローソン銀行」(ATM) がコンビニに入っている。UI ではなくデータ側の問題。
- **ログ**: `POI_DB prefecture=広島県 ...` が 1 秒ごとに出続けている。動作には影響しないが、ログが読みにくくなる。
- **横向き**: 起動直後、横向きのときに右側のボタン群がカテゴリのチップと重なっていた (回転中の 1 枚だけで、再現は未確認)。

## よくできている点

- 検索バー、種類の絞り込み、右側に縦に並ぶボタン、下部の 3 タブという配置が整理されていて、迷いにくい。
- POI 詳細は名前・種類・距離・住所・「ここへ行く」・「保存」がまとまっている。
- ルートプレビューの 3 つのモード (おすすめ・平坦優先・坂道優先) と標高グラフは、自転車向けらしい良い点。
- ナビの終了確認、到着予定時刻、「この先は平坦」の表示もわかりやすい。
- 3D 表示の建物と地形はきれいで、動きも軽い。
