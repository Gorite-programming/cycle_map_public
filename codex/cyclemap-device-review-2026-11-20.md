# CycleMap Galaxy S26 実機検証レポート

2026年11月20日、Galaxy S26をADBで操作して、オフラインでの出発準備からナビ・走行記録までを確認した。優先して直したいのは、県またぎナビ開始直後の再計算、サイコンを抜けた後のGPX記録状態の分かりにくさ、文字サイズ200%での走行情報の欠落。

## 検証条件

| 項目 | 条件 |
|---|---|
| 端末 | Galaxy S26（SC-51G）、Android 17 |
| APK | `α0.9.11-unified-win`、`com.gorite.cyclemap.test.win` |
| ビルド | `1d9403e-dirty`、APK SHA-256先頭12桁 `a07410935af2` |
| 通信 | 機内モード有効、Wi-Fi無効、Androidの既定ネットワークなし |
| オフラインデータ | 地図・検索・経路データを47都道府県分配置。端末の管理画面では合計27.3 GB |
| 経路 | 広島市内から岩国駅方面（約30.7 km）と、広島市内からLECT（約3.6〜3.7 km） |
| 表示条件 | 縦・横画面、文字サイズ100%・200%。ADB操作時は端末を静止 |

## 優先して修正したい点

### 高 — 県またぎナビが開始直後に再計算される

広島市内から岩国駅方面へ平坦優先でナビを開始した2回とも、静止したまま約2〜3秒後に再計算が始まった。再表示まで約5.1秒かかり、画面に「ルートを再計算中」と探索中の表示が出た。近距離のLECT行きでは開始直後の再計算を観測しなかった。文字サイズ変更などで画面が再生成された際にも再計算を観測した。

出発直後の経路逸脱判定と設定変更時の経路復元を調べる。現在地から道路への接続区間、測位精度、経路上の最近傍点をログで突き合わせる。再検証では、静止したまま開始したときに不要な再計算が発生せず、実際に経路を外れたときは再計算できることを確認する。

### 高 — サイコンの一時停止とGPX記録状態を見分けにくい

静止中、サイコンは「一時停止」、距離は `0 m` を表示した。「通常へ」を長押しして地図に戻り、ナビを終了しても、ホームには「記録を止める（76点）」が出ていた。記録はホームから停止した。「ルートなしで走る」も、押すとその場でGPX記録が始まった。

「自動一時停止」と「GPX記録中」をそれぞれ表示する。サイコンに「記録を終了して保存」を用意し、ナビ終了後も記録を続ける場合は確認画面で伝える。ホームの「ルートなしで走る」にも記録開始が分かる文言を添える。

### 高 — 文字サイズ200%で走行情報が欠ける

横画面のサイコンで、現在速度の単位が初期表示に収まらなかった。平均・最高速度はスクロールしても `km` までしか見えなかった。縦画面では距離・時間の数値が初期表示の下に隠れた。横画面のナビではコンパスの方位文字が重なった。

速度と `km/h` を一体で配置する。文字拡大時は指標カードの列数を減らし、現在速度・次の案内・残距離を優先する。長押しの説明を対象ボタン側に寄せ、走行情報を表示する高さを確保する。

### 中 — 同じ駅とみられる候補が重複する

「岩国」と「岩国駅」が履歴に別々に並び、どちらも現在地から25.8 kmと表示された。座標差は約6 mで、地図上でも別ラベルとして現れた。「いわくに」と入力した際は、「いちばん合う」とされた駅の上に郵便局が2件表示された。

名称の表記差・鉄道カテゴリ・近接座標を使って、同一施設の候補をまとめる。用途の異なる出入口は個別に選べるようにする。最有力候補の強調と表示順も揃える。

### 中 — 横画面で到着時刻が食い違い、バナーが地図を遮る

同じナビ画面で、上段は `01:45 到着`、下段は `01:46` だった。県またぎの通知が現在地矢印の一部に重なる場面もあった。

到着時刻の計算と丸めを共通化する。県またぎの案内はプレビューでも確認できるため、ナビ中の通知を短くして地図中央の視界を確保する。

## UI改善と追加機能の候補

| 項目 | 実機での所見と提案 |
|---|---|
| 検索範囲 | 「導入済みの全県」が初期表示では右端で切れ、横にスワイプすると全文が見えた。短いラベルやメニューで選択範囲を示す。0件の場合は結果画面から範囲を広げられるようにする。 |
| ルート全体表示 | LECT行きでは代替ルートのカードが出るとプレビューが高くなり、出発側の地図が隠れた。シートの実測高さを考慮してルートを収めるか、「全体を見る」でシートを縮める操作を追加する。 |
| 立ち寄り確認 | 横画面の一覧で最初に読める候補は1件。「立ち寄る」の次は「地点の指定」と表示され、選んだ店名が消えた。確認画面に店名を残し、追加後も経由地名を確認できるようにする。 |
| オフライン準備 | 詳細では県とデータ種別の組み合わせが縦に並び、2県でも下部が画面外に出た。県ごとに必須項目の充足状況を要約し、不足時は対象県とデータ種別を先頭に表示して県別のデータ管理につなげる。 |
| 案内停止と再開 | 現状の終了確認は案内停止と設定済みルートの消去がセット。「案内を停止してルートを保持」を追加し、休憩後に経由地を含めた行程を再開できるようにする。 |
| オフライン時の天気 | ネットワーク切断後もホームに `5°・雨20%` が表示された。予報の最終取得時刻が分かる表示を添える。 |

## 正常動作を確認した範囲

- 機内モードかつWi-Fiオフで、地図表示、かな入力での目的地検索、広島・山口をまたぐ経路探索、標高プロファイル、ナビ開始、コンビニ検索と経由地追加まで操作できた。
- 県またぎ経路の初回表示はログ上で約3.6秒。平坦優先への切り替えは約5.2秒だった。
- LECT行きでは `3.6 km・約14分` と `3.7 km・約15分` の代替候補を切り替えられ、地図・距離・時間・標高グラフが更新された。
- ナビ中に縦横を切り替えても地図と案内が表示された。サイコンから地図へ戻った際も描画され、既知の白紙化は今回の手順では再現しなかった。
- 短時間の静止中、サイコンで `0 m・最高0.0 km/h` を確認した。記録停止後にGPXファイルが生成されたことを端末のファイル一覧で確認した。

## 残る確認

- 実際に県境を通過したときの地図・検索データ切り替え。県境の先にある立ち寄り候補の並び。
- 走行中の音声案内、GPS途絶後の復帰、実際に経路から外れた際のリルート。
- 押し歩き時の距離積算、長時間の静止ドリフト、バッテリーへの影響。
- GPXの内容、記録停止直後の再開、サイコンからの保存。
- 必須の県別データが不足する条件での診断と復旧。別端末およびTalkBackでの操作。

検証後にGPX記録を停止し、機内モード・Wi-Fi・文字サイズ・画面回転を検証前の設定に戻した。端末には検証で作成したGPXが2件と、目的地検索の履歴が残っている。
