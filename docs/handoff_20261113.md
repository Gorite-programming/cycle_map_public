- **全県対応の下ごしらえ** (`f08fd85`, `eead09a`): `scripts/prefectures.py` に 47 県の定義 (JIS コード・Romaji・地方区分) を一本化し、`build_prefectures.py` / `build_tiles.py` / `build_terrain.py` / `build_ch.py` / `build_portals.py` / `refresh_data.py` の県リストをそこに差し替えた。`--only` は県名・地方名・`all` を受け付ける。既定 (`--only` 省略) は従来どおり中国5県。`scripts/_platform.py` で Windows/Mac の差 (gradlew.bat、pmtiles/osmium の探索、JDK 探索) を吸収。
- **osmium extract の一括化** (`eead09a`): 県ごとに個別 extract すると全国 PBF (2GB超) を県の数だけスキャンすることになる (1県で約65秒)。`osmium extract -c <config>` で複数県をまとめ、スキャンを1回にした (`batch_extract()`)。2件未満や失敗時は個別 extract にフォールバックする。兵庫+岡山の実機検証で、ノード/辺数が個別抽出と完全一致、所要時間は2県合計293秒 (個別なら推定390秒)。
- **兵庫1県・兵庫+岡山2県の試験生成**: ZIP (5点構成)・CH サイドカー・PMTiles いずれも生成でき、PMTiles検証・検索DB整合性・CHとA*の1000件完全一致 (mismatch=0) を確認済み。1県あたりの実測: graph+ZIP 約110〜207秒、CH 約110秒、タイル取得 約17〜20秒。北海道・沖縄・東京など離島/広域県は未試験 (境界の外接矩形が広く、タイル取得の分割が別途必要)。
- **見つけて直したバグ3件**:
  1. `osm-importer` が Windows で道路名を Shift-JIS で出力し、`build_prefectures.py` 側が UTF-8 decode で読んでいたため道路名を含む県でクラッシュしていた (`run_live()` に `errors="replace"` を追加、`080bb26`)。
  2. `sandbox/data-tool` の `config.PREFECTURES` が (未レビューのまま取り込んだ以前の変更で) 47県に拡張済みだったのに、テストが旧5県前提のままで CI が落ちていた (`d0ed8c4`)。
  3. `build_prefectures.py` が sandbox に残っていた古いタイルを ZIP 横へコピーし、`build_tiles.py` が有効な既存ファイルとしてスキップする問題 (沖縄では `--force` で回避)。2026-11-15 恒久対応: sandbox からのコピーを廃止し、タイルの作成・更新は `scripts/build_tiles.py` に一本化。`build_prefectures.py` は `packages/<県小文字>.pmtiles` の既存ファイルだけを参照し、タイルなしでも5点構成の ZIP を生成する。
- **Windows + 日本語パスで `./gradlew test` が動かない (未解決、ローカル限定)**: プロジェクトパスに日本語が含まれていると、Gradle がテスト実行用クラスパスを書き出す一時ファイル (`@gradle-worker-classpathNNN.txt`) の中身 (UTF-8) を、Windows 側がおそらく ANSI コードページで読み違え、`build/classes/...` のパスが文字化けして「クラスが見つからない」で全テストが落ちる。デーモン再起動・キャッシュ削除・`-Dsun.jnu.encoding=UTF-8`・ASCIIパスへのジャンクションいずれも効果なし (ジャンクション越しでも Gradle が実体パスに解決し直すため)。今回は英数字パス (`C:\dev\cycle_map`) へ物理的に移動して解消 (動作未確認、次回要検証)。GitHub Actions (Linux, ASCII パス) には影響しない。
- **CI のフレーキーテスト**: `AdaptiveRerouteTest > triggersRerouteAfterThreeConsecutiveDeviations` (`:app:testReleaseUnitTest`) が、Kotlin を一切触っていない push で単発で落ちた (直前の push は成功)。コルーチン・バックグラウンドスレッドのタイミングに依存するテストで、再実行で通った。繰り返す場合は待ち合わせ (`join()`) の前後の assert 順序を見直す。

### Codex への委譲 (Claude が親、Codex が子)
- Claude が設計・タスク分割・検証を行い、実装とテストの実行を Codex に委譲する。指示文 (Markdown: 背景 / 触ってよいファイル / 守ること / 受け入れ条件 / 実行するテスト) を `work/codex/` に書き、`scripts/delegate_codex.sh <指示文>` で渡す (`--readonly` で読み取り専用)。出力は画面とログ (`work/codex/*.log`) に流れるので、Terminal パネルで進行を見られる。
- Codex は同じ作業ツリーで作業する。commit / push / adb / 履歴を壊す git 操作は禁止 (ラッパーの前置きで指示済み)。Gradle は動くようサンドボックスに network と `~/.gradle` の書き込みを許可している。
- Claude は返ってきた diff を必ず読み、テストを自分でも実行してから commit する。実機検証は Claude が必要と判断したときだけ行い (UI の出方・待ち時間・スレッド競合に関わる変更など)、Codex には触らせない。
