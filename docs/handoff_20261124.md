### 直していないもの (低い優先度。評価で本物と判定済み)

- `NavigationHelper.kt`: ヘッダーは、経路に投影した残り距離だけで「到着しました」を出す。そのため、並行する道にいても出ることがある。
- `WaypointRoutePlanner.kt`: 経由地を通る探索で、別の出発ノードを試さない (条件はかなり限られる)。
- `CrossRoutePlanning.kt`: 最少の県数の候補 (最大 3 本) がすべて失敗すると、それより長い県の並びを試さない。
- `LocationTrackingService.kt`: ドップラー速度の無い測位で、1 m 未満の移動は速度 0 になる。その速度で上書きするので、`RideSession` の「速度なし」の経路が使われない。
- `RouteGpx.kt`: GPX を経路として読み込むと、`trkseg` の区間の間を直線で結ぶ。
- `GraphContractionHierarchy.kt`: CH の暖機は `graphLock` 無しで走る (結果は壊れない。汚れるのはログ用の値だけ)。
- `LocationTrackingService.kt:194`: 復元するジャーナルを、ランダムな UUID のファイル名順で選んでいる。

## 4. 実機で確かめてほしいこと (Galaxy S26)

1. 位置情報の権限を外した状態で、サイコンの「開始」を押す。落ちずに「位置情報の権限が無いため記録を開始できません」の Toast が出ること。
2. 長い道路区間 (ノードの間が 200 m 超) の途中を出発地にする。経路の線が出発地から始まり、距離が欠けないこと。
3. 県をまたぐ経路 (山口→広島など) で、県境の通り口や経由地で曲がるときに、音声とバナーの案内が出ること。
4. 山口県で起動し、最初の経路で「山口県のグラフに切替中です」が出ないこと。
5. 記録を一時停止し、数分おいてから再開する。走行時間に休止時間が入らないこと。

`scripts/device_regression.sh` も一度回すこと。

## 5. 広島県の列車の推定位置 (`wip/hiroshima-rail`)

- 頼んだこと: Gorite が Codex に頼んだ。広島県内の私鉄と JR の列車の予測位置を地図に出す。
- 仕様:
  - 時刻表から、端末の中だけで位置を推定する (遅延は反映しない)。
  - 対象は JR (新幹線を含む)・広島電鉄・アストラムライン・井原鉄道。
  - 設定パネルのスイッチで表示し、タップで行先と次の駅を出す。
- 進み具合 (Codex がトークン切れで止めた時点):
  - `scripts/build_hiroshima_rail.py` は、GTFS と OSM の線路から `packages/hiroshima.rail.db` (約 25 MB) を作る。中身は、駅間の区間 93,916 件と線路の形 570 本。
  - `rail/RailTimetable.kt` と `rail/RailMapLayer.kt` がある。設定のスイッチ、`MapViewsContainer` への組み込み、`push_data.sh` の転送も入っている。
  - 残り:
    - 線路の対応づけができない区間がある (アストラムの白島周辺、福山↔備後本庄、姫路・神戸方面)。線路を取り出す範囲を広げたところで止まった。
    - 最新のコードでビルドが通るか確かめていない。
    - テストと docs を書いていない。
- **重要: 時刻表データの利用条件が不明。**
  - `https://jbb.ghsq.de/gtfs/jp-jr.gtfs.zip` は、個人が運営する置き場のファイルで、説明・作成者・元データ・ライセンスのどれも書かれていない。
  - `feed_info.txt` の配布者は「jr-gtfs」で、URL は `https://example.com/` のまま。
  - JR の `agency_url` は JR サイバーステーション。そこから集めた可能性がある。
  - このデータを使っている Transitous の設定 (jp.json) でも、ライセンスの欄が空。
  - **このデータで作った DB やアプリを配布・公開しない。**
- 公式のデータ:
  - 広島電鉄の GTFS は Transitland に載っている (`f-hiroden~jp`)。ただし、ライセンスと路面電車を含むかは未確認。
  - JR 西日本・アストラムライン・井原鉄道は、公式の公開データが見つからなかった。
- 続けるなら:
  1. 広島電鉄の公式 GTFS の利用条件を確かめ、それに差し替えて路面電車だけで完成させる。
  2. 他の路線は、公式のデータが出るか、各社の許可が得られてから加える。
  3. 設定の説明文にある「時刻表：jp-jr」の表記も差し替える。

## 6. Windows で始めるときの手順

```bash
git pull
git log --oneline -8
```

- `wip/hiroshima-rail` は、続けるときだけ `git switch wip/hiroshima-rail` で切り替える。データ (`packages/hiroshima.rail.db`、`work/rail/`) は Mac にしか無いので、`scripts/build_hiroshima_rail.py` で作り直す必要がある。スクリプトの冒頭が指している `application/docs/hiroshima_rail.md` は、まだ書かれていない。Codex が使った入力の作り方は次のとおり (時刻表を公式のデータに差し替えるなら、`jp-jr` は取得しない)。

```bash
mkdir -p work/rail
curl -fL https://jbb.ghsq.de/gtfs/jp-jr.gtfs.zip -o work/rail/jp-jr.zip   # 利用条件が不明 (5 章)
osmium extract -b 130.30,33.53,135.60,35.54 --strategy complete_ways data/japan-latest.osm.pbf -o work/rail/rail-region.osm.pbf --overwrite
osmium tags-filter work/rail/rail-region.osm.pbf w/railway=rail,tram,light_rail,subway,monorail n/railway=station,halt,tram_stop -o work/rail/railways.osm.pbf --overwrite
```
- 3 章の修正は Gradle のテストで確かめてあるが、実機はまだ。4 章から始めるのがよい。
