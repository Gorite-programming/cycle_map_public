# 車線の自動判定 — 三者の意見の突き合わせ (2026-11-17)

Gorite の要望: アプリに **(1) どこを走っているか** と **(2) どこを通れるか** を判定させたい。データは OSM のタグ + 端末のセンサー (カメラは使わない)。
Claude・Codex・Antigravity が、同じ依頼文 (`work/codex/lane_detect_design.md`) に別々に答えた。以下は、その突き合わせ。まだ実装はしない。

## 1. 三者が一致したこと

1. **車道の左端・自転車レーン・歩道・路側帯の「どれを走っているか」(道の中の横位置) は、GPS とセンサーでは安定して判定できない。** 日本の道は、これらの間が 1〜3 m しか離れていないのに、GPS の誤差は 5〜15 m ある。「分からないときは言わない」を守ると、ほぼ常に「不明」になる。→ 一般機能として約束しない。
2. **加速度の振動は、車道と歩道の判定の決め手にならない** (舗装・タイヤ・空気圧・取付具・速度で変わる)。気圧計は、高架と地上のような大きな高さの違いにしか効かない。
3. **進行方位と辺の向きの差による「逆走」の検知は、実用になる。** (速度が 1.5 m/s 以上で、精度が良いときだけ。)
4. **タグが無いことは、「設備が無い」「通れない」の証拠にならない。** タグ無しの一般道は「車道の左側が原則」。歩道は、通行を許可するタグが無ければ「情報なし」とし、通れると断定しない。
5. **道路の「一致」(どの道か) と、道路の中の「場所」は、別々に評価する。** 並走する別の道 (数 m 離れた自転車道など) の識別は、候補を複数持って履歴で判断すれば、ある程度できる。
6. **属性の表示だけなら、辺の順番と重みを変えないので、CH (高速索引) を作り直さずに済む。** 経路探索に反映する段階で、はじめて CH のやり直しが要る。
7. **見せ方**: 「あなたは歩道を走っています」のような断定は出さない。出してよいのは、「この道のルール (車道左側が原則 / 左側に自転車通行帯の登録あり)」と、確度が高いもの (逆走注意、この先は自転車通行不可・押し歩き)。「車道へ戻ってください」のような操作の指示は出さない。
8. **MVP**: センサーによる横位置の推定は外す。「タグ → 通行ルールの分類」と「スナップした道のルール表示」と「逆走の検知」から始める。

## 3. 新しく分かったこと・直すべき前提

- 私の依頼文の「歩道は標識があるときだけ」は不正確だった (Codex の指摘)。文言は「通行可の登録の有無」に直す。
- 今の importer は `bicycle=no` / `dismount` と、`bicycle` タグの無い `footway` を **graph から外している**。このため、「禁止道に入った」の検知は、第 2 段のサイドカーが無いと誤吸着になる (Antigravity の指摘。Codex も同じ)。
- 日本の OSM は `sidewalk:bicycle` や `cycleway` が欠けている道が多く、大半が既定値になる。**まず 1 県の短い区間で、タグの充足率と、既存の辺への対応率を測ってから**、全県に広げるかを決める (Codex)。
- 並走路の識別と逆走の検知は、実機で、**誤断定率・不明率・表示の遅れ・電池**を測らないと、公開してよいか決められない。シミュレーション (SIMLOC) の成功だけでは合格にしない。

## 4. 提案する作り方 (決まったら進める)

要望 (2) 「どこを通れるか」は、**「通行ルールの表示」として作る**。要望 (1) 「どこを走っているか」は、**「どの道か」「逆走」「並走する別の道」までに絞る**。道の中の横位置 (車道左端・歩道・路側帯) は、作らない。

1. **タグの分類器** (`routing-core`、JVM、テストしやすい純粋な関数): OSM のタグ → 左右それぞれの設備 + 自転車の通行条件 (乗車可 / 条件つき / 乗車不可 / 押し歩き / 不明) + フラグ。表形式のテストで、タグの優先順位 (`bicycle` → `vehicle` → `access` → `highway`)、左右の反転 (`oneway=-1`・辺の向き)、条件つき・矛盾を網羅する。
2. **importer の「属性だけ作る」モード**: 既存の graph の辺の順に、分類を `.graph.idx` の末尾に追記する。広島 1 県で試し、タグの充足率と辺への対応率を測る。
3. **マップマッチング + 逆走の検知** (`app`、JVM でテスト): 候補 3 つ + 履歴 5 秒。「不明」の条件は、精度 15 m 超・低速・拮抗・交差点など。実走の記録 (候補・棄却理由・精度) を残す。
4. **表示**: 現在の道のルールを、控えめなバッジで。逆走と、この先の通行不可だけ強めの警告。不明のときは出さない。
5. **実機での計測**: 広島の短い回廊で、離れた並走路の識別・逆走・誤断定率・電池を測る。
6. (第 2 段・あとで) 除外した道のサイドカーと、経路探索への反映 (CH のやり直しを伴う)。

## 5. Gorite に決めてほしいこと

1. 要望を上の形に**絞って**よいか (道の中の横位置は作らない)。
2. データの置き場は、第 1 段 `.graph.idx` 末尾 + 第 2 段サイドカー、でよいか。
3. 最初の試験は、広島県の短い区間でよいか。
