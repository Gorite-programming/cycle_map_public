# コードから見た問題点の棚卸し (2026-11-26)

実機をつなげない日に、サブエージェント 5 体へ読み取り専用でコードを読ませ、バックエンドの問題と、コードから推測した UI の問題を集めた。Google マップとの使いやすさの比較点数も付けさせた。

- 視点: ① 経路探索の正しさ (`:routing-core`・`:osm-importer`)、② データの読み込み・性能・Python のパイプライン、③ 走行中の案内、④ 出発前の計画・検索、⑤ 地図の見やすさ・初めての人・アクセシビリティ。
- 実機・エミュレーターでは何も確かめていない。UI の評価は Compose のコードと resource からの推測。
- Google マップの点数は、エージェントの一般知識と `docs/offline_map_baseline.md` による。参考値として扱う。
- 「検証済」は、Claude (親) が該当箇所のコードを読んで、指摘どおりであることを確かめたもの。それ以外はエージェントの報告のまま。
- 既に `docs/handoff_20261124.md`・`docs/session_20261125.md` に載っている項目は「既知」と書いた。
- パスは、Kotlin のアプリは `application/app/src/main/java/com/gorite/cyclemap/` から、それ以外はリポジトリの根からの相対パス。

## 総評

- **経路探索の中核は健全。** A*・CH・RPHAST・県またぎの通り口・mmap の読み込みに、誤った経路やコストの食い違いは見つからなかった (`:routing-core:test` 全件成功)。
- **弱いのは「その周り」。**
  - 案内: 音声と画面で選ぶ案内が違う。外れたことが表示されない。
  - 計画: 出発地を選べない。経由地に名前もピンも無い。「道の駅」が検索できない。
  - データ投入: 端末への転送が途中で切れると壊れたファイルが残る。それをアプリが数秒ごとに読み直し続ける。
- **Google に勝つ点**: 完全オフライン。坂を見て経路を選べる (等高線・陰影・「登りが◯m少ない」)。誤操作への配慮。
- **Google に大きく負ける点**: 初回の導入 (データの手動導入)。自転車道を地図で区別できない。音声案内の質。出発地・経由地の扱い。

## Medium

### 走行中の案内
- **画面オフ中の再計算が追跡に反映されない疑い** (要確認): Compose が ON_STOP で再構成を止めるため、案内の処理が古い経路・古い `lastRerouteElapsedMs` のまま動く可能性がある。案内の状態を ViewModel かサービスに移すのが本筋。`ui/effects/MapTrackingEffects.kt:180-297`
- **横画面の案内バー**: 矢印 24dp。距離が丸められず毎秒変わる。飾りのアニメが幅 116dp を取る。ライトテーマは白文字/緑で 3.5:1。`ui/map/NavigationHudViews.kt:313-371` (コントラストは既知の項目と関連)
- **音声の予告距離が固定** (300/100/30m): 速いときに間に合わない。近い連続の曲がり角を「その先」でつながない。`speech/VoiceGuidance.kt:55-62`
- **再計算が進行方向を見ない**: Uターンの経路が返りうる (たぶん)。`ui/screens/MapScreen.kt:789-791`
- **バナーのタップで全面の一覧が開き、曲がり角が近づいても閉じない**: `ui/layout/MapTopOverlays.kt:239-249`、`ui/components/StepListDialog.kt`
- **縦画面の下パネルが既定で開いている**: 地図が画面の半分近くまで減る (たぶん)。`ui/map/NavigationPanelC.kt:338-339`
- **通知・ロック画面に曲がり角が出ない**: `tracking/LocationTrackingService.kt:451-459`

### 経路探索・データ
- **曲がり角の分類が、自転車で通れない motorway の枝も分岐として数える**: 国道の直進中に高速の入口ランプがあると「右上分岐」と案内しうる。`navigation/NavigationHelper.kt:73-81` (`outgoingBranches` は全辺を返す)、`navigation/CrossRouteMerging.kt:77-82`
- **県またぎの終点を「出ていける向き」だけで孤立判定している**: 終点に必要なのは「入ってこられるか」。県またぎは引き直さないので経路全体が失敗しうる。`routing-core/.../SnapFallbackRouting.kt:90-124` (検証済)
- **県をまたぐ経路 1 本で、同じ隣県のグラフを最大 3 回読み直す**: `navigation/MultiLegRoutePlanner.kt:140-149, 204, 333, 479`
- **道路ルールの索引づくりが `-Xmx4g` 固定でデータ工房のメモリ枠の外。失敗しても rc 0 で終わる**: `build_prefectures.py:50, 655-658`
- **古い CH が気付かれずに残る**: データ工房は `.graph.ch` があれば CH ジョブを作らない。診断画面はファイルがあるだけで「使える」と出す。`scripts/studio_plan.py:122, 163`、`data/OfflineReadiness.kt:70`
- **廃道系の highway 値** (`disused`・`razed`・`dismantled`・`planned`・`no`) が除外されず、`OTHER = 1.15` で住宅街の道より安い: `osm-importer/.../OsmImporter.kt:57-60` (検証済)。直すと graph・CH・portals の作り直しが要る。

## 問題なしと確かめたもの

- A* のヒューリスティックの許容性 (辺の距離は importer も haversine、係数の下限 0.90 を A* と CH の前処理で共有)。
- CH の近道の展開・平行辺の重複除去・RPHAST の順序・mmap の大きさの検査。
- `build_prefectures.py` の約束 (ZIP は 5 ファイル、`--strategy complete_ways`、`--bbox none`、失敗した work の保持、統合 DB の検証)。
- CH・ポータル・タイル・地形・DEM キャッシュ・検索 DB の書き込みの原子性。アプリ内取り込みの `.part` による置き換え。
- 出典表記は地図の下の専用の帯に常に表示され、パネルに隠れない。

## 次に直すときの順番の案

1. **数行で済み効果が大きい**: H1 (道の駅の検索)、Uターンの矢印、H7 (ON_RESUME で権限を読み直す)、ラスター地図の DPI と背景の上書き。
2. **案内の信頼性**: H2 (音声の案内の選び方を画面とそろえる)、H3 (外れた表示と手動の再計算)、motorway の枝を分岐から除く。
3. **データ投入の堅さ**: H9 (`.part` に送り、SHA-256 を確かめてから mv)、H10 (失敗したファイルを覚えて読み直さない)、`.bikerules` の昇格。
4. **計画の画面**: H4 (出発地)、H5 (ベクター地図の経由地のピン)、経由地の名前。
5. **地図**: H6 (自転車道の色と通行不可の道の表示。スタイルの変更なので `patch_map_style.py` と `StyleJsonTest` も)。

実機が使えるようになったら確かめること: 画面オフ中の再計算、横画面の案内バーの読みやすさ、大きな文字の設定での切れ、FTS5 の判定の logcat。
