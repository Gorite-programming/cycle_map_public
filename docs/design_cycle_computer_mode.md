# サイコンモードの設計 (2026-11-17)

地図を出さず、速度・距離・時間を大きく見せる「サイクルコンピュータ」画面。ハンドルに付けたスマホで、走りながら一瞥で読めることを目的にする。
表示モードは 3 つ (通常 / サイコン / シンプル) の 1 つで、シンプルモード (地図だけ) と利き手モードは別の設計。ここではサイコンモードと、3 モードに共通の土台だけを決める。

## 1. 決まっていること (Gorite 2026-11-16〜17)

- 地図は出さない。
- 目的地は、**走り出す前に**通常画面で決めておける。モード中に検索はしない。
- 目的地があるときは、**方向と残り距離**が分かる。
- 項目は「速度と距離、時間など」。

## 2. 表示する項目

| 項目 | 元の値 | 備考 |
| :--- | :--- | :--- |
| 現在速度 | `Location.speed` (m/s) を 3 点で平滑化 | 最も大きく出す。停止中は 0 |
| 走行距離 | 位置の差を足す (精度 20 m 以下、速度 0.5 m/s 以上のときだけ) | 停止中の GPS のゆれで増えない |
| 走行時間 | 動いていた時間 (自動一時停止中は止まる) | 経過時間は別に持つ |
| 平均速度 | 走行距離 ÷ 走行時間 | |
| 最高速度 | 平滑化後の最大 | |
| 獲得標高 | 気圧計があればそれ、無ければ GPS の高度を平滑化 | 後述 |
| 時刻 | 端末の時計 | 上端に小さく |
| 目的地までの方向と残り距離 | 目的地があるとき | 後述 |
| (ルートがあるとき) 次の曲がり角 | 既存の案内 (`navigationProgress`) | 通常の案内と同じ値を出す |

標準の画面は 1 ページに 4〜6 項目。横にスワイプして 2 ページ目 (標高・最高速度・ラップなど) を見る。項目の入れ替え (カスタマイズ) は後で。

## 3. 目的地の方向と残り距離

- ルートがあるとき (通常画面で決めておいた場合): 残り距離は道なり (`RouteProgress.remaining`)、方向は**次の曲がり角の矢印と距離**を出す。
- ルートが無く、目的地だけがあるとき: **直線距離**と、現在の進行方向に対する**相対方位の矢印** (磁北ではなく進行方向基準) を出す。残り距離の横に「直線」と書く。
- どちらも無いときは、その欄を出さない (項目の位置は詰めない。数字が動かないように、空欄で残す)。

## 4. 状態の持ち方

新しい純粋なクラス `RideSession` (`tracking/`、JVM でテストできるように Android に依存させない) を置く。

```
RideSession.onLocation(timeMs, lat, lon, speedMps?, accuracyM, altitudeM?, pressureHpa?)
RideSession.snapshot(nowMs): RideSnapshot(
  speedKmh, distanceM, movingTimeS, elapsedS, averageKmh, maxKmh, elevationGainM, state)
RideSession.pause() / resume() / reset()   // state: IDLE / RUNNING / PAUSED
```

- 自動一時停止: 速度が 2 km/h 未満の状態が 3 秒続いたら PAUSED、2 km/h 以上が 1 秒続いたら RUNNING に戻る。手動の一時停止もできる。
- 位置は既存の `LocationTrackingService` のリスナーから受ける (新しい位置取得は増やさない)。サービスが動いている間は、モードを切り替えても値が続く。
- 走行記録 (GPX、`GpxRecorder`) とは独立。記録を開始すると `RideSession` も RUNNING にし、記録を止めると止める。記録せずにサイコンだけ使うこともできる。
- アプリが落ちても値が消えないよう、1 分ごとと一時停止のときに `SharedPreferences` へ退避する (`ride_session_v1`)。起動時に 30 分以内のものがあれば「続きから」を聞く。

## 5. 画面の構成

`DisplayMode { NORMAL, CYCLE_COMPUTER, SIMPLE }` を `cyclemap_prefs` の `display_mode` に保存する (既定 NORMAL)。

- `MapScreen` の最上位で、`CYCLE_COMPUTER` のときは地図 (MapLibre / osmdroid) を作らず `CycleComputerScreen` を出す。地図を作らないので、メモリ・電池の節約にもなる。
- ただし位置・ルート・案内の状態 (`MapViewModel`) は同じものを使い続ける。モードの切り替えでルートや案内を失わない。
- 切り替えの入口: 設定の「表示モード」と、通常画面のメニュー。サイコン画面からは、大きめの「モード切替」ボタン (誤操作しないよう長押し)。
- 縦持ち・横持ちの両方に対応する。縦: 速度を上に大きく、下に 2 列の小さな項目。横: 左に速度、右に項目。

## 6. 電源・画面

- サイコン画面の間は画面を点けたままにする (`FLAG_KEEP_SCREEN_ON`)。ただし、走っていない (PAUSED が 60 秒続いた) ときは通常の消灯に任せる。
- 既存の省電力 (`isLowPowerMode`) のときは、更新を 1 秒に 1 回にし、輝度を下げる案内を出す。
- 画面は暗い背景に大きな数字 (既存のダークテーマの「墨と朱」)。日中の見やすさのため、コントラストを高くした表示も用意する。

## 7. 標高の取り方

- 端末に気圧計があれば、気圧の変化から高度差を出す (GPS の高度より滑らか)。起動時の気圧は、既存の標高データ (`elevationMetersAt`) か GPS で較正する。
- 無ければ GPS の高度を移動平均 (5 点) で平滑化し、3 m 未満の変動は数えない。
- どちらも獲得標高は「登った分の合計」。

## 8. テスト

- `RideSessionTest` (JVM): 停止中のゆれで距離が増えない、自動一時停止の入り・戻り、平均速度、獲得標高の閾値、退避と復元。
- 表示の整形 (速度・時間・距離の文字列) は純粋な関数にして単体テスト。
- 実機: `SIMLOC` で動かして、速度・距離・時間・目的地の方向が出ることを確かめる。

## 9. 作る順番

1. `RideSession` とそのテスト (JVM、Codex に任せられる範囲)。
2. 表示の整形関数と、`CycleComputerScreen` (縦・横)。
3. `display_mode` の保存と、`MapScreen` での切り替え。
4. 目的地の方向と残り距離。
5. 画面常時点灯・電源まわり。
6. 退避と復元、標高 (気圧計)。
7. 実機確認。

シンプルモードと利き手モードは、3 の「表示モードの土台」ができてから作る。

## 10. 決めたこと (2026-11-17 Gorite)

- 縦持ちを既定にする (横にも対応)。ラップは入れない。標高は気圧計を使う。自動一時停止は 2 km/h 未満が 3 秒。外部センサーは含めない。

## 11. 実装の状況 (2026-11-17)

- 済み: `RideSession` (位置の飛び 50 m/s 超は距離に足さない)、`RideFormat`、`CycleComputerScreen`(縦・横)、表示モードの保存 (`display_mode`)、設定の「表示モード」、ルートプレビューの「サイコン」ボタン (ナビを始めてからサイコン画面にする)、目的地欄 (道なり残り+次の曲がり / 直線+向き)、画面の常時点灯。
- 済み (2026-11-17 追加): 気圧計 (`PressureReader`、サイコン画面を出している間だけ動かし、`RideSession` に気圧を渡して獲得標高を出す)、走行の退避と復元 (`RideSessionStore`、`cyclemap_prefs` の `ride_session_v1`。サイコン画面の間 15 秒ごと・離れるときに保存し、起動時に 30 分以内のものを**一時停止**で戻す。リセットで消す)。
  実機 (S26) で、走らせたあとアプリを強制終了して再起動すると、距離・時間・平均・最高が一時停止で戻り、「再開」で続けられることを確認した。気圧計は端末にある (BOSCH bmp5) が、実際に登って獲得標高が増えることは未確認 (静止中は +0 m のまま安定)。
- 済み (2026-11-17 追加): サイコンの間は地図 (MapLibre / osmdroid) を作らない (`MapViewsContainer` の `mapsSuspended`。位置・ルート・案内の状態は残り、戻ると地図が作り直される)。実機 (S26) で、`dumpsys meminfo` の Graphics が通常 約 130 MB → サイコン 約 73 MB に減り、通常に戻すと地図・ルート・案内が復帰することを確認した。
- 未: 直線の目的地の向きの実機確認、横持ちのサイコン画面の実機確認、電池の減りの実測。

## 12. 走行記録のモード横断復元の調査 (2026-11-20、第P波)

今回追加したのは `RideRecordingRestorePolicy` と単体テストのみ。以下の統合は未実装で、通常画面での退避や GPX との照合が有効になったわけではない。GPX の保存・復旧と既存の統計の復元処理は変更していない。

### 現行で食い違う箇所

- `MapScreen` が `RideSessionStore.restore()` で統計を生成し、位置更新を渡すため、通常・サイコン・シンプルの表示切替だけでは統計インスタンスは変わらない。`distanceOrigin` も `toState` / `fromState` に含まれる。復元時の `pause()` で `previous` と共に消すのは、停止中の移動を距離に足さないための意図した挙動。
- 15 秒ごとの退避と画面を離れるときの退避は `CycleComputerHost` の中だけ。`MapScreen` にも記録状態変化時の退避はあるが、通常・シンプルで記録を続けてプロセスが終了すると、最後のサイコン表示時などの古い値に戻るか、退避がなく統計を失う。
- GPX はサービスが所有し、journal のランダム UUID ファイル名と `START` の開始時刻を持つ。統計は別に自動開始でき、`startedMs` は同じ記録開始を意味しない。両者の走行 ID は未共有。
- サービスの `restorePendingRecording()` はファイル名順で journal を選び、一時停止で戻す。一方、統計は単一の SharedPreferences エントリから 30 分以内かだけで復元する。復旧ダイアログの「続ける」はその統計を開始するため、別 journal の統計を混ぜる可能性がある。GPX は復旧できても統計だけ期限切れになる場合もある。
- 気圧計はサイコン表示中だけなので、表示モード間で標高の供給源も変わる。GPS 高度へ切り替える際の基準差は既存ロジックで加算を防いでいるが、同じ精度の獲得標高が保証されるわけではない。

### 追加した純粋ポリシー

`RideRecordingRestorePolicy.encode()` は統計の退避文字列に `recordingId` を添える。`decideRestore()` は、選択した journal の ID が退避された ID と完全一致するときだけ既存の期限・破損・未開始の検証へ進み、一時停止で返す。欠落・空・制御文字を含む ID、別 ID、ID のない旧形式は照合できないものとして拒否する。時刻の近さによる推測はしない。不一致の退避データは別 journal に属する可能性があるので、この純粋関数は削除しない。既存の 30 分制限は維持している。

### 次の統合案 (今回の編集範囲外を含む)

1. journal ファイル名の UUID をサービス側の記録 ID とし、新規開始・復旧選択・保存完了後に次の journal を選ぶとき、その ID と統計をひと組で公開する。既存 journal の形式は変更しなくてよい。開始時刻では衝突や統計の自動開始とのずれがあるため照合しない。
2. 統計の所有・位置入力・15 秒退避をサービスへ集約する。表示モードや Activity の有無に関係なく更新する。`MapScreen` の生成・位置入力・開始/一時停止・保存時のリセットと `CycleComputerHost` の退避を同時に置き換え、二重加算や古い UI からの上書きを防ぐ。気圧入力の所有も合わせて決める。
3. journal を選んでから対応する ID の統計だけを復元する。旧形式や不一致なら統計を混ぜず、新しい統計として扱う。GPX の継続/保存は統計の有無にかかわらず今までどおり可能にする。30 分を超えた同一 journal の統計を戻す要否と、複数の未保存 journal を扱う ID 別保存は別途決める。
4. 保存失敗では ID と統計を保持する。成功時は保存対象の ID だけを終了し、次の復旧候補の統計を消さない。サービスの非同期保存と UI のリセットをまとめて検証する。

統合には今回許可されていない `ui/screens/MapScreen.kt` の変更と、UI からサービスへの統計所有権の移行が必要。GPX の保存・復旧への影響を避けるため、今回の縮退範囲では実施しない。次の統合時には全モードでの記録・プロセス終了復旧・別 ID・旧退避・複数 journal・保存失敗を検証する。
